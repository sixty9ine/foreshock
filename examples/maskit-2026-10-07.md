# Provenance — maskit-2026-10-07

Captured against `Cd8LqgfpwzxjtU8YwrK9BvFwtR2FvPAHVbLZrVwpump` with the
`insiderFlow` build from the same day, which classified pool addresses by
appearance frequency alone (`POOL_FREQUENCY_SHARE`, no counterparty-breadth
check yet).

That frequency-only heuristic had a confirmed bug: a wash-trading wallet
round-tripping against the pool could cross the frequency threshold through
self-churn alone and get silently excluded as a "pool" — precisely the
wallet insiderFlow exists to catch. Fixed the same day by requiring both
frequency *and* counterparty breadth (`POOL_DETECTION` in
`src/scorer/thresholds.ts`); see that commit for the full repro.

**This file is unaffected.** Re-running the same mint after the fix produced
an identical report — same composite (76), same phase (`quiet`), same
`insiderFlow` cohort and evidence down to the number. MASKIT's early cohort
did not happen to include a wash-trader that the old heuristic would have
misclassified, so the stored JSON needed no replacement. Checked, not
assumed.
